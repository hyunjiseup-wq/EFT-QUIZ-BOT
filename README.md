# 타르코프 지식 퀴즈 봇

*[English](README_EN.md)*

이스케이프 프롬 타르코프의 구조/시스템/스토리 지식을 테스트하는 디스코드 퀴즈 봇입니다.
4지선다 버튼 방식이며, `questions.json`에 **총 464문제**의
기출 풀이 들어있습니다. 매 판(세션)마다 이 풀에서 난이도별로 **일반 2 · 중간 3 · 어려움 15 · 고난이도 10 (총 30문제)**를
랜덤 추출하고 순서까지 섞어서 출제하므로, 같은 사람이 여러 번 도전해도 매번 다른 조합의 문제를 만나게 되고
기출 문제가 커뮤니티에 공유되더라도 효과가 제한적입니다.

추출 개수는 `config.py`의 `SESSION_COUNTS`에서 조정할 수 있습니다 (단, 각 난이도 풀 크기 이상으로 늘릴 수는 없어요).

## 현재 운영 구성

| 항목 | 현행 값 |
|---|---|
| 문제 은행 | 총 464문제 — 공통 451 · PvP 전용 11 · PvE 전용 2 |
| 모드별 출제 가능 | PvP 462문제(`common+pvp`) · PvE 453문제(`common+pve`) |
| 세션 구성 | 일반 2 · 중간 3 · 어려움 15 · 고난이도 10 = 총 30문제 |
| 최대 점수 | 1,380점 |
| 문제 제한 시간 | 문제당 20초 |
| 동시 세션 보호 | 서버당 기본 250개 |
| Discord UI | 이용자 대시보드 1종 · 감독 대시보드 1종 · 전용 아이콘 21종 |
| 슬래시 명령어 | 이용자 8개 · 관리자 6개 = 총 14개 |
| 데이터 저장 | 서버별·PvP/PvE별 SQLite 집계 + 개별 완주 이력, WAL 사용 |

PvP/PvE 표시는 **퀴즈 문제 풀을 나누기 위한 모드 태그**입니다. PvP 전용 11문제에는
Kord Breach 시즌처럼 PvP 쪽에서만 성립하는 항목이 포함되고, PvE 전용 2문제에는 PvE Zone에서
답이 달라지는 항목만 들어갑니다. 보험처럼 PvP 영구 프로필과 PvE에 공통으로 적용되는 내용은
`common`으로 분류합니다.

## 명령어

### 모든 서버 이용자

| 명령어 | 공개 범위 | 기능 |
|---|---|---|
| `/pvp퀴즈` | 본인만 | 공통 + PvP 전용 문제로 30문제 시작 |
| `/pve퀴즈` | 본인만 | 공통 + PvE 전용 문제로 30문제 시작 |
| `/타르코프퀴즈포기` | 본인만 | 진행 중 세션 종료, 기록 미저장 |
| `/pvp퀴즈랭킹` | 채널 공개 | 해당 서버 PvP TOP 10 |
| `/pve퀴즈랭킹` | 채널 공개 | 해당 서버 PvE TOP 10 |
| `/퀴즈참가현황` | 채널 공개 | 서버 고유 참가자와 모드별 누적 완주 수 |
| `/pvp퀴즈기록` | 본인만 | 본인의 PvP 최고·최근·누적 기록 |
| `/pve퀴즈기록` | 본인만 | 본인의 PvE 최고·최근·누적 기록 |

랭킹과 참가 현황은 서버 이용자 모두 확인할 수 있습니다. 개인 기록과 실제 퀴즈 화면만
ephemeral로 본인에게 표시됩니다.

### 서버 관리자

| 명령어 | 기능 |
|---|---|
| `/퀴즈대시보드설치` | 현재 채널의 이용자 대시보드 설치·갱신 |
| `/감독대시보드설치` | 현재 채널의 감독 대시보드 설치·갱신 |
| `/대시보드아이콘설치` | 누락된 전용 아이콘만 등록하고 설정된 두 대시보드 갱신 |
| `/퀴즈봇상태점검` | DB·문제 풀·세션·채널 권한·대시보드·아이콘 읽기 전용 점검 |
| `/히든상품후보 [기간일]` | 감독 채널에서 최다 완주·참여 일수·성장·언더독·올라운더 후보 조회 |
| `/타르코프퀴즈랭킹초기화` | 확인 버튼 후 해당 서버의 랭킹과 전체 응시 기록 삭제 |

관리자 명령어는 Discord 기본 권한과 런타임 관리자 검사를 함께 사용합니다. 히든 상품 후보는
자동 당첨 결과가 아니라 관리자 검토 자료이며, `/히든상품후보`는 설정된 감독 채널에서만 실행됩니다.

랭킹 초기화는 **저장된 결과만 삭제**하며 진행 중인 세션을 중단하지 않습니다. 그 세션이 나중에
완료되면 기록이 다시 생깁니다. 이벤트 전 초기화는 신규 응시를 제한하고 활성 세션이 없는지
감독 대시보드에서 확인한 뒤 실행하세요. 운영 DB는 먼저 백업하세요.

## 동작 방식

- 퀴즈 채널의 **이용자 대시보드**에서 **PvP 시작 · PvE 시작 · 튜토리얼 · 모드별 랭킹 · 내 기록** 버튼을 사용할 수 있습니다.
  `.env`에 `QUIZ_CHANNEL_ID`가 설정되어 있으면 봇 시작 시 해당 채널에 자동 설치·갱신됩니다
  (여러 서버에서 운영한다면 쉼표로 구분해 서버마다 하나씩 적습니다).
  수동으로는 서버 관리자가 원하는 채널에서 `/퀴즈대시보드설치`를 실행할 수 있으며, 다시 실행하면
  DB에 저장한 메시지 ID → 고정 메시지 → 최근 100개 메시지 순으로 기존 대시보드를 찾아 갱신합니다.
  자동 고정을 시도하며, 권한 부족이나 API 오류로 고정에 실패해도 설치는 유지됩니다.
  봇을 재시작해도 버튼은 계속 작동합니다.
- 관리자 검토 채널에는 별도의 **감독 대시보드**가 설치됩니다.
  `.env`의 `ADMIN_LOG_CHANNEL_ID`를 기준으로 자동 설치되며 **참가 현황 · 히든 후보 30일 ·
  활성 세션 · PvP/PvE 랭킹** 버튼을 제공합니다. 버튼은 서버 관리자만 사용할 수 있습니다.
  이 설정도 쉼표로 여러 채널을 받으며, 관전 로그와 감독 기능은 각 서버에 설정된 채널로 갑니다.
- 두 대시보드와 퀴즈 알림은 `assets/dashboard_icons/`의 타르코프풍 전용 아이콘 21종
  (대시보드 10종 · 알림 11종)을 지원합니다.
  서버 관리자가 `/대시보드아이콘설치`를 한 번 실행하면 없는 커스텀 이모지만 등록하고
  설정된 퀴즈·감독 대시보드를 즉시 갱신합니다. 같은 이름의 기존 이모지는 삭제하거나 덮어쓰지 않으며,
  아이콘이 설치되지 않은 서버에서는 기존 기본 이모지를 계속 사용합니다.
- 퀴즈는 명령어를 실행한 사람에게만 보이는(ephemeral) 메시지로 진행됩니다.
  같은 채널에서 여러 명이 동시에 명령어를 실행해도 각자 자신의 화면만 보고, 서로의 진행 상황은 보이지 않습니다.
  `.env`의 `QUIZ_CHANNEL_ID`에 채널 ID를 설정하면 **그 채널에서만** 퀴즈를 시작할 수 있습니다
  (다른 채널에서 시도하면 그 서버에 설정된 채널로 안내. `0` 또는 미설정이면 모든 채널 허용).
  여러 서버에서 운영한다면 `QUIZ_CHANNEL_ID=111..., 222...`처럼 쉼표로 이어 적습니다.
  서버당 채널 하나만 지정하세요. 대시보드 위치는 (서버, 종류)당 하나만 저장되므로
  한 서버에 둘 이상을 적으면 뒤의 채널은 무시하고 경고 로그만 남깁니다.
- 문제당 제한시간 20초 (`config.py`의 `QUESTION_TIME_LIMIT`에서 조정 가능). 시간 초과 시 오답 처리 후 다음 문제로 자동 진행됩니다.
- **문제의 난이도/배점, 정답/오답 여부, 정답과 해설은 응시자에게 표시되지 않습니다.**
  답변 제출 시 "제출되었습니다"만 표시되고(시간 초과 시에는 시간 초과 안내), 진행 중 점수도 보이지 않습니다.
  정오답 내역과 난이도별 현황은 관리자 관전 로그에서만 확인할 수 있습니다.
- 문제를 다 풀면 최종 점수와 정답 수가 표시되고, 기록이 저장됩니다.
- 랭킹은 최고 점수 기준이며, 랭킹의 정답 수는 최고 점수 세션이 아니라 모든 완주의
  **누적 정답 수**입니다.

랭킹과 개인 기록은 디스코드 서버와 PvP/PvE 모드별로 분리됩니다. 모드 분리 전에 생성된
기록은 삭제하지 않고 `mode=legacy` 영역에 보존되며 새 모드 랭킹에는 표시되지 않습니다.
서버 분리 기능 도입 전에 만들어진 DB를
처음 실행하면 기존 행은 삭제되지 않고 `guild_id=0`인 레거시 영역으로 자동 이전됩니다.
구버전 DB에는 서버 ID가 저장되지 않았기 때문에 해당 기록은 실제 서버 랭킹에는 표시되지 않습니다.

히든 상품 후보 계산을 위해 각 완주의 점수·정답 수·시간 초과 수·소요 시간과 완료 시각을
`quiz_attempts` 테이블에 별도로 저장합니다. 기존 랭킹 집계는 그대로 유지되며,
**성장·언더독·활동 일수 후보는 이 기능을 배포한 이후의 완주부터 계산**됩니다.
언더독 후보는 고의 오답을 줄이기 위해 1문제 이상 정답이고 시간 초과가 전체 문제의 절반 이하인
정상 완주만 포함합니다. 후보는 자동 당첨자가 아니므로 지급 전에 관리자 검토가 필요합니다.

## ⚠️ 알려진 제약: 15분 인터랙션 토큰

디스코드의 ephemeral 메시지는 최초 인터랙션 후 약 15분이 지나면 봇이 임의로 수정할 수 없습니다.
버튼을 누르면 새 인터랙션이 생겨 문제없지만, **장시간 방치해서 시간초과가 연달아 발생하는 경우**
15분 이후에는 메시지 갱신이 실패할 수 있습니다. 이 경우 봇이 세션을 자동 정리하므로
`/pvp퀴즈` 또는 `/pve퀴즈`로 새로 시작하면 됩니다.

## ⚠️ 디스코드 구조상의 한계 — 관리자 관전

디스코드의 ephemeral 메시지는 **관리자를 포함해 그 누구도 응시자 본인 외에는 볼 수 없습니다.**
이건 디스코드 플랫폼 자체의 제약이라 봇 코드로 우회할 수 없어요.

그래서 이 봇은 대신 **관리자 전용 "관전 로그" 채널**을 사용합니다. 응시자가 퀴즈를 시작하면
그 채널에 **세션당 로그 메시지 1개**가 생성됩니다. 답변은 매번 메모리에 기록하지만 Discord 메시지는
기본 **5문제마다** 묶어서 갱신하므로 화면의 점수·정오답 이력은 즉시 반영되지 않을 수 있습니다.
완료·포기 시 마지막 상태를 반영합니다. API 요청이 실패하면 관전 로그가 누락될 수 있습니다.
**오답/시간초과 문항에는 응시자가 고른 보기 · 정답 · 해설이 함께 기록**되므로,
응시자가 "왜 오답이냐"고 문의하면 관리자가 로그만 보고 바로 답변할 수 있습니다.
메시지를 문제마다 새로 보내지 않는 이유는 동시 응시자가 많을 때 채널 도배와
디스코드 레이트리밋을 피하기 위해서입니다.
`.env`의 `ADMIN_LOG_CHANNEL_ID`에 채널 ID를 설정하면 활성화됩니다
(채널은 관리자만 볼 수 있게 서버에서 권한을 설정해주세요).
여러 서버에서 운영한다면 쉼표로 서버마다 하나씩 적습니다.
채널이 설정되지 않은 서버에서는 퀴즈는 정상 진행되고 관전 로그만 남지 않습니다.

## 설치

Python **3.10 이상**이 필요합니다. 이 프로젝트는 discord.py 2.6 이상 API를 사용합니다.

```bash
pip install -r requirements.txt
cp .env.example .env
# .env 파일에 DISCORD_TOKEN(필수), ADMIN_LOG_CHANNEL_ID, QUIZ_CHANNEL_ID 입력
python bot.py
```

### 디스코드 개발자 포털 설정
- Bot 권한: `applications.commands`, `bot` scope. 대시보드 자동 고정에는 **메시지 관리**,
  전용 아이콘 설치에는 **표현물 만들기** 또는 **이모지 및 스티커 관리** 권한도 허용
- 채널 권한: 퀴즈 채널에 "채널 보기", "메시지 보내기", "메시지 기록 보기", "슬래시 명령어 사용" 허용
- 관전 로그 채널: 봇에게 "메시지 보내기" 권한, 일반 유저는 채널 안 보이게 권한 설정

## 대규모 이벤트 보호

- SQLite는 시작 시 WAL 모드와 30초 busy timeout을 적용해 결과 저장과 랭킹 조회가 겹쳐도
  `database is locked` 오류가 쉽게 발생하지 않도록 합니다.
- DB 스키마는 SQLite `user_version`으로 관리합니다(현재 v2). 현재 봇보다 새로운 스키마의
  DB를 발견하면 구버전 코드가 데이터를 변경하지 않도록 시작을 중단합니다.
- 랭킹 전용 인덱스를 사용하고, 히든 상품 후보는 전체 완주 목록을 메모리에 적재하지 않고
  순차 집계합니다.
- 관리자 관전 로그는 Discord 레이트리밋 대기를 백그라운드에서 처리하고, 대기 중 쌓인 변경은
  최신 상태로 병합합니다. 답변 기록은 메시지 생성 전에도 메모리에 즉시 보존하며, 기본 5문제마다
  묶어 갱신하고 완료·포기 상태를 마지막으로 반영합니다.
- 한 서버의 동시 진행 세션은 기본 250개로 제한합니다. 상한에 도달하면 진행 중 세션이
  끝날 때까지 신규 시작만 잠시 제한하며 기존 퀴즈는 계속 진행됩니다.
- 같은 사용자의 동시 시작은 첫 세션을 먼저 예약해 중복 생성을 막고, 시작 화면 전송이나
  포기 로그 정리가 실패해도 활성 세션 레지스트리를 자동으로 회수합니다.
- 포기 명령은 먼저 비공개 응답을 예약하므로 관리자 로그 API가 느려도 Discord의 3초 응답
  제한을 넘기지 않습니다. 완료·시간 초과 화면을 잃어버린 세션도 자동 중단·정리됩니다.
- Discord 로그는 루트 로거 하나만 사용해 동일한 로그인·게이트웨이 메시지가 중복 출력되지
  않습니다. CI는 PR에서 한 번, `main` 병합 후 한 번만 실행됩니다.
- 생성·갱신된 퀴즈/감독 대시보드 메시지 ID를 DB에 저장합니다. 고정 권한이 없거나 메시지가
  최근 기록 100개 밖으로 밀려도 재시작 시 기존 메시지를 직접 찾아 중복 생성을 방지합니다.
- 대시보드에는 버전을 표시하지 않습니다. 내부 버튼 ID와 기존 v1·v2 footer를 함께 인식해
  예전 메시지도 같은 위치에서 footer 없는 화면으로 갱신합니다.
- `python load_test.py`는 운영 DB를 건드리지 않는 임시 DB에 8,500명·25,500회 응시를 만들고,
  공개 통계·랭킹·히든 상품 후보, 동시 랭킹 조회 200회, 동시 세션 250개 예약과 251번째
  시작 거절, 전체 세션 정리를 검증합니다. 세션 수는 `--sessions`로 바꿀 수 있습니다.

필요하면 `.env`에서 `MAX_ACTIVE_SESSIONS_PER_GUILD`와 `ADMIN_LOG_UPDATE_EVERY`를 조정할 수
있습니다. 동시 세션 상한은 전체 서버 인원수가 아니라 **같은 순간에 진행 중인 퀴즈 수**입니다.

## 문제 추가/수정

`questions.json`에 아래 형식으로 항목을 추가하면 됩니다.

```json
{
  "id": 31,
  "mode": "common",
  "difficulty": "medium",
  "category": "무기",
  "question": "문제 내용",
  "choices": ["보기1", "보기2", "보기3", "보기4"],
  "answer": 0,
  "explanation": "정답 해설 (응시자에게 노출 안 됨, 관전 로그의 오답 기록에 사용)"
}
```

`difficulty`는 `general`(일반) / `medium`(중간) / `hard`(어려움) / `expert`(고난이도) 중 하나이며,
배점은 `config.py`의 `POINTS` 딕셔너리에서 조정합니다.

`category`는 문제의 파트(주제) 분류로 **스토리 · 퀘스트 · 맵 · 보스·AI · 상인 · 무기 · 탄약 ·
장비 · 의료·식량 · 하이드아웃 · 스킬 · 시스템** 12종 중 하나입니다 (출제 로직에는 영향 없고
관리용). `python check_questions.py`가 파트별 문제 수를 보여주고,
`python check_questions.py --category 탄약`처럼 특정 파트의 문제 목록을 뽑을 수 있습니다.

`mode`는 `common`, `pvp`, `pve` 중 하나이며 생략하면 `common`으로 처리됩니다.
PvP 퀴즈는 `common+pvp`, PvE 퀴즈는 `common+pve` 문제만 출제합니다. 모드에 따라
정답이 달라지는 문제는 지문에도 시즌명, 패치 버전 또는 PvE Zone 기준을 명시하세요.

문제를 추가/수정한 뒤에는 `python check_questions.py`로 형식(보기 4개, 정답 인덱스, 중복,
파트명 등)을 검증하세요. 봇은 시작할 때만 `questions.json`을 읽으므로 **수정 후 봇 재시작이 필요합니다.**
봇 시작 시에도 동일한 검증을 수행하며 오류가 있으면 잘못된 문제로 실행하지 않고 즉시 중단합니다.

## 점검 및 테스트

```bash
python check_questions.py
python load_test.py
python -m unittest discover -s tests -v
python -m py_compile admin_log.py bot.py config.py dashboard_icon_installer.py dashboard_installation.py database.py dashboard_manager.py interaction_access.py operations_check.py question_bank.py quiz_completion.py quiz_icons.py quiz_lifecycle.py quiz_presenters.py quiz_reports.py quiz_scoring.py quiz_session.py check_questions.py load_test.py
ruff check .
```

`main`으로의 push와 PR 생성·갱신 시 Python 3.10과 3.13에서 CI 검사가 실행됩니다.
PR 없는 작업 브랜치의 push만으로는 실행되지 않습니다. CI는 각 `tests/test_*.py`를 별도
프로세스로 실행하며, 통과는 코드·데이터 형식 검증이지 게임 지식의 사실성 보증이 아닙니다.

VS Code에서는 저장소에 포함된 `.vscode/settings.json`이 프로젝트의
`.venv\\Scripts\\python.exe`와 `unittest` 검색 경로를 자동으로 선택합니다.

Windows에서는 `봇실행.bat`가 `.venv`의 Python을 먼저 실행해 상태를 확인합니다. 기존 Python이
제거되어 가상환경이 깨진 경우 해당 가상환경을 지우고 현재 설치된 Python으로 다시 구성합니다.

> **배치 파일 인코딩 주의:** `봇실행.bat`은 한국어 Windows의 `cmd.exe` 호환을 위해
> **CP949 + CRLF**로 유지합니다. UTF-8로 다시 저장하거나 파일 안에 `chcp 65001`을 추가하지
> 마세요. `.gitattributes`도 체크아웃된 배치 파일에 같은 인코딩을 적용하도록 설정되어 있습니다.

## 🔁 패치 변동형(volatile) 문제 관리

해금 레벨, 시설 수치, 퀘스트 조건처럼 **게임 패치로 정답이 바뀔 수 있는 문제**에는
`"volatile": true`와 점검 메모 `"volatile_note"` 필드가 붙어 있습니다 (봇 동작에는 영향 없음).

게임 패치가 나오면:

1. `python check_questions.py --volatile` — 변동형 문제 목록과 현재 정답을 확인
2. 패치 노트/위키와 대조해 정답이 바뀐 문제의 `choices` / `answer` / `explanation`을 수정
3. `python check_questions.py` 로 형식 검증 후 봇 재시작

새로 만드는 문제도 패치 영향을 받을 수 있는 내용이면 `volatile` 필드를 붙여두세요.
보스 상주 맵처럼 이벤트로만 일시 변경되는 항목은 상시 배치 기준으로 출제되어 있습니다.

남은 보스·AI 15문항도 대조해 일반 야간 컬티스트와 등대 경비대, 레이드 중 해독과 다른
치료, 전리품 가능성과 확정 드롭을 구분했습니다. 산타 문항은 2025년 Kolotun 당시의

하이드아웃·기본 시스템 23문항도 대조했습니다. 홀 오브 페임의 보너스 조건, 방어구의
Class 0 표기와 원래 최대 내구도, 에디션·진영의 예외를 명확히 했습니다. 하이드아웃
29문항 모두 근거를 기록했으나 최신 게임 실측 완료는 아닙니다. 미니맵·킬피드 문항은
현재 본편 UI를 직접 확인할 근거가 부족해 확인 완료로 표시하지 않았습니다.
스토리 42문항도 대조해 28문항을 보완했습니다. 출시 이력과 진영 음성 설명을 고치고,
일부 목표와 챕터 전체 완료, 엔딩 서술과 달성 조건, 위키 추론과 확정 설정을 구분했습니다.
스토리 전 문항에 근거를 기록했지만 세부 분기·최신 모드별 실측이 끝났다는 뜻은 아닙니다.

취급하지 않습니다. 버그 상태·세부 수치의 남은 재검증 목록도 검수 기록을 참고하세요.

## 참고

타르코프는 2025년 말 1.0 정식 출시 이후에도 패치가 계속되고 있어, 문제는 패치에 잘 변하지 않는
구조적 지식(진영/하이드아웃 개념/시큐어 컨테이너/보험 등)과 스토리 위주로 구성했습니다.
탄약 대미지/관통력 문제(id 178~201)는 위키 [Ballistics](https://escapefromtarkov.fandom.com/wiki/Ballistics)
표 기준으로 출제했으며 전부 `volatile`로 표시되어 있으니, 밸런스 패치 후에는
`python check_questions.py --volatile`로 점검하고 위키 표와 대조해 갱신하세요.
